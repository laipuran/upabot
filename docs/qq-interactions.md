# QQ 互动：上下文与动作工具

插件目录与标识：`plugins/astrbot_plugin_qq_reaction_listener/`；显示名 **QQ Interaction Memory**，版本 `v0.4.1`。目前仅支持 QQ 群聊，基于真实 AstrBot 4.29.3 SDK 开发。裸机部署脚本已包含此插件，具体功能开关在 WebUI 管理。

**总开关和主动动作默认关闭。** 开启主动动作后，群白名单为空允许所有群，非空仅允许指定群；感知和被戳文字回复不受此白名单限制。

## 功能

### 感知互动与被戳回复

- 接收别人戳机器人的群通知，以及给机器人群消息新增/撤销表情回应。
- 表情回应只更新短期记忆，不触发模型；用只读 `get_msg` 确认消息作者为当前机器人。给其他人的消息贴表情不记录，别人互戳不参与。
- 首个有效戳事件**立即**生成原生 `ProviderRequest`，沿用当前会话、人格与聊天历史，要求一句简短文字回复；不额外等待 3 秒，不先进行“要不要回复”的 JSON 决策，也不因刚进行过正常聊天而屏蔽 30 秒。
- 连续戳仍会记入计数，但默认同群 3 秒内只启动首轮回复，避免一次连戳产生多轮。每群最多 20 次/分钟、插件实例最多 60 次/分钟的戳回复准备尝试；不是承诺 QQ 官方允许的频率。
- “当场”指不人为延迟触发，仍需等待原生会话队列和模型生成。模型未启用、不可用、超限、会话已停用插件或读取会话失败时不能保证回复；插件不编造模型输出。
- 戳回复只允许文字，不开放工具，避免只回戳或调用语音后不说话。保留正常的 AstrBot 内容安全、人格和历史链路；模型错误、重试和流式策略由原生配置管理。
- 通知的 UUID 不是真实 QQ 消息号。本插件仅在该戳事件的 `send` 接口过滤指向通知 UUID 的引用段，避免全局“引用回复”配置造成无效引用；不修改其他消息和平台设置。发送前再次检查开关与来源，停用/卸载后阻止尚未发起的戳回复发送。

正常聊天及戳回复的模型请求中，只附加最近相关互动：操作者、次数或原消息摘要、实际表情编号和名称、已完成回复状态。附加数据明确不是用户新指令，未知名称为 `null`，不猜测情绪、关系或社交意图。

短期记忆只存内存：默认有效 600 秒，最多 128 个会话、每会话 32 条，每次请求最多 8 条；每条摘要最多 300 字、最多 20 个表情。读取不续期，过期按后续操作惰性清理，无后台清理任务。隔离平台实例、机器人 QQ 和 AstrBot 会话来源。

重复上报、乱序表情撤销、自身操作、未知操作者及畸形通知均做过滤。同一个操作者同一秒内、上游没有唯一标识的多个戳可能无法区分而被折叠；完全没有标识/时间时不假装能可靠去重。`get_msg` 每会话每分钟最多 8 次，10 秒超时，结果/失败缓存，失败静默跳过。

互动块通过 `TextPart.mark_as_temp()` 交给模型，标准 AstrBot 历史序列化不会保存该块，也不会整表注入表情。戳事件通过明确标记“非用户文字”的触发提示进入原生会话，其正常回复可被记录；模型提供商、调试日志及其他插件的留存策略不由本插件控制。

### 主动动作工具

开启插件总开关和“允许主动动作”后，模型可自主调用以下两个工具，没有对应的聊天命令。群白名单为空时允许所有群，非空时仅允许指定群；关闭主动动作时无论白名单如何均禁止发送。工具在 `initialize()` 中动态注册，关闭时不注册；请求阶段也按平台、群和会话权限过滤，实际调用时重新检查。人格或管理员没有授予的工具不会被强行追加进请求。

#### `qq_interaction_poke`

```json
{"target": "sender"}
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `target` | `sender` | `sender` 当前发言人；`quoted_sender` 引用消息作者；`mentioned` 当前消息里唯一被 @ 的人 |
| `finish_turn` | `true` | 成功后结束本轮，不再让模型补发动作描述；还需回答实质问题时设 `false` |

只戳一次。不接受任意 QQ、昵称、次数或全体成员。多个被 @ 的候选不猜测。引用目标会查询原消息，确认属于当前群并读取实际作者，不直接信任模型或引用摘要里的 QQ 号。

#### `qq_interaction_react`

```json
{"target": "quoted", "emoji": "捂脸"}
```

```json
{"target": "current", "emoji": "264", "finish_turn": false}
```

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `target` | `current` | `current` 当前消息；`quoted` 用户引用的消息 |
| `emoji` | 必填 | 十进制表情编号或准确名称，不再使用五个英文别名 |
| `finish_turn` | `true` | 与戳工具相同 |

原消息号只能从当前事件/引用解析，不接受模型指定的任意消息 ID。引用消息必须确认属于当前群。一个调用贴一个表情，不是发表情包或一条普通表情消息。

成功后默认返回 AstrBot 的结束本轮信号（`None`），避免再生成“我戳了你/我贴了表情”。若 `finish_turn=false`，结果只交给模型，并明确要求不播报动作，保留回答实际问题的能力。调用前已输出的流式文字无法撤回；`false` 模式的自然表达仍依赖模型，不能承诺完全没有重复描述。失败时不返回成功信号，更不会假装执行过动作。

## 表情表不整表注入

本地 `emoji_names.json` 固定了 537 个编号—名称映射，来自 QFace 的 QQ 索引，详见插件目录的 `EMOJI-SOURCE.md` 与 `LICENSE-QFace.txt`。仅包含数字编号与文字名称，不包含图片/动画。

- 收到回应时，仅为本次实际出现的编号补名称。
- 发送时在本地按编号/名称查找；重名或名称不准确时返回最多 8 个候选，模型再明确选择编号。未发送的查表失败不消耗发送额度。
- 表不出现在系统提示词、每轮上下文或工具参数描述中；不新增一个必须先调用的查询工具，不在运行时联网。
- 名称不等于情感。表中存在不代表当前 QQ/NapCat 版本支持用它贴消息回应，未知编号不能发送；平台拒绝时不会试别的编号或自动重试。

## 发送限制与开关

两个动作工具共用一个发送执行模块：

- 同一条真实 QQ 群消息最多尝试一个动作，戳和贴表情互斥；并发调用和模型重复调用也不能重复发送。
- 默认同群间隔 3 秒、每群每分钟最多 12 次；整个插件实例工具尝试最多 60 次/分钟。
- 校验通过后、网络调用前原子预占额度，发送失败或超时也占用额度，避免不确定投递后的重复发送。10 秒超时，插件不自动重试或补发。
- 必须同时满足总开关、主动动作开关、群范围规则（空白名单不限群）、平台/真实消息来源、本地 Agent 模式、模型配置及会话插件权限。查引用/读权限期间来源或开关变化则重新校验当前规则。
- 限额仅在本插件内共享，不能限制语音、其他插件或机器人正常文字聊天；也不把“已开始普通聊天”视为禁止被戳回复。冷却和去重是内存状态，重启后不保留。

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `false` | 总开关 |
| `context_enabled` | `true` | 感知并自动附上下文 |
| `poke_reply_enabled` | `true` | 感知开启时，被戳立即触发文字回复 |
| `context_ttl_seconds` | `600` | 记忆有效秒数，10～3600 |
| `poke_reply_cooldown_seconds` | `3` | 连戳防重复秒数，1～10；首个不等待 |
| `tools_enabled` | `false` | 允许 AI 在普通聊天中主动戳人、贴表情 |
| `tool_groups` | `[]` | 群白名单；主动动作开启后，空列表允许所有群，非空仅允许指定群 |
| `tool_cooldown_seconds` | `3` | 两工具共享发送间隔，1～60 秒 |
| `tool_limit_per_minute` | `12` | 两工具共享每群每分钟尝试数，1～120 |

只用感知与被戳回复：`enabled=true`，其他使用默认值。允许所有群的主动动作：`enabled=true`、`tools_enabled=true`、`tool_groups=[]`；只允许指定群时填写 `tool_groups`。只用主动动作、不感知互动时另外设置 `context_enabled=false`。配置保存后需要正常重载插件以更新注册状态。

旧稿中的 `proactive_enabled`、`proactive_groups`、`proactive_reactions`、`merge_wait_seconds`、`proactive_cooldown_seconds`、`decision_timeout_seconds` 及旧 JSON 决策后台调度不再生效。主动动作由 `tools_enabled` 控制，`tool_groups` 仅用于缩小生效群范围。总开关开启且感知启用后，戳回复默认立即生效；若只需静默记忆，设置 `poke_reply_enabled=false`。

## 本地验证与尚未实测的范围

测试使用真实 AstrBot SDK，替换外部模型和 QQ I/O，不启动真实账号。覆盖原生通知转换/模型流水线、被戳立即触发与连戳去重、临时上下文序列化、小范围名称附加、动态工具注册/隐藏/卸载、默认成功后结束本轮、绑定目标、跨群拒绝、查询竞态、并发防重复、共享额度与失败不重试。

运行：`python -m unittest discover -s tests -q`、`ruff check .`、`ruff format --check .`。本机使用 `/tmp/opencode/upabot-venv`，不覆盖原 `.venv`。旧调度器及其对应测试已替换，不保留两套相互冲突的自动回应实现。

本次全仓库 **122 项测试通过**，lint、格式和 diff 空白检查通过；537 项表情映射已逐项与固定提交的原始索引核对。所有外部发送/模型接口均使用模拟对象，未真实调用。

尚未进行真实模型自然度/工具选择测试、完整 WebUI/容器启动验收或真实 QQ 收发、风控与部署验证。不能据模拟结果宣称线上验收通过。私聊、关系画像、不受限的任意目标操作不在当前范围。

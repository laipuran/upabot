# 电费插件：选房、查询和低余额报警

`/电费` 和 `/elec` 是同一个入口，直接执行插件代码，不调用 Agent。暂不设置权限限制，群成员都可以管理当前群的绑定和报警。

## 交互式绑定房间

发送 `/elec subscribe`，依次回复编号：区域 → 楼宇 → 楼层 → 房间 → “确认”。不需要手动填写 RoomId。对话中同时只能有一个选择流程，只处理发起者的回复；其他成员和普通聊天不会被当作选择。回复“返回”“取消”，或发送 `/elec cancel`，可退回或结束；五分钟无操作后过期，重启插件也会结束未完成的交互。

每个私聊或群聊只绑定一个房间。群成员共享同一绑定，不受 LLM 的按成员会话隔离影响；不同平台实例、不同群、群聊与私聊互不共享。多个对话可以选择同一个房间。RoomId 等标识按字符串保存，保留前导零。

后端接受订阅后才写入绑定。实际接口可能返回 `202`，表示订阅已建立而历史回填仍在进行；返回 `409` 已订阅也可以完成绑定。查询无数据时稍后重试，不会自动刷新。更换过程中保留旧绑定，失败、取消或超时都不会丢失它。

| 命令 | 功能 |
| --- | --- |
| `/elec`、`/elec help` | 帮助 |
| `/elec subscribe` | 交互选择并订阅 |
| `/elec room` | 当前房间名称和 RoomId |
| `/elec change` | 重新选择，确认后替换 |
| `/elec unsubscribe` | 确认后解除本对话绑定，不停止后端房间跟踪 |
| `/elec cancel` | 发起者取消当前交互 |
| `/elec balance` | 最新缓存余额及记录日期 |
| `/elec usage [YYYY-MM-DD]` | 日用量与电费，默认昨日 |
| `/elec trend [开始日期 结束日期]` | 三合一趋势图，默认最近七个完整自然日 |
| `/elec refresh` | 显式触发后端更新 |

默认日期按北京时间计算，不能查询未来日期。趋势日期必须成对提供、起始不晚于结束，最多366天；缺失日期不补零、不跨缺失日期连线，全部无数据时只提示文本。

## 配置报警

| 命令 | 功能 |
| --- | --- |
| `/elec alert on 10` | 余额低于10元时通知 |
| `/elec alert off` | 关闭报警 |
| `/elec alert` | 查看阈值、最近检查时间与状态 |

报警默认关闭。金额必须大于0，最多两位小数、整数最多9位。开启后在下次定期检查生效；默认每小时检查一次，插件重启后重新计时。首次检查发现低余额也会通知，持续低余额不会重复发送；余额恢复到阈值或更高后，再次跌破才重新通知。重复设置同一个阈值不重置去重状态。

更换房间保留阈值，但清除旧房间的报警和检查状态；解绑清除当前对话的全部设置。绑定、阈值、去重状态和检查结果保存到 `astrbot/data/plugin_data/astrbot_plugin_electricity/electricity.sqlite3`，不保存余额缓存，重启后仍然有效。

每次检查直接调用后端余额接口，不自动刷新，也不自动重试请求。后端限流、无数据或失败时保留原报警状态，记录检查错误，等待下轮检查。通知失败不消耗报警机会，下轮重试；QQ 发送成功后、去重状态写入前若进程崩溃，仍存在重复通知的窗口，不能保证严格的恰好一次投递。

机器人没有房间余额缓存。同一轮报警按房间查询一次，再按各对话的阈值分别通知，响应在本轮结束后不保留；下一轮和人工查询仍直接请求后端。这样不会因为同一房间绑定多个对话而在一轮内重复消耗后端额度。人工查询仍可能与报警检查碰到后端限流，`429` 会直接提示或跳过本轮；后端有缓存不代表查询接口没有限流。报警时效取决于后端数据更新频率，通知注明余额记录日期，不承诺实时余额。群消息和主动私信的最终送达也受 QQ 平台限制。

## 部署配置

```dotenv
ELEC_API_BASE_URL=http://host.docker.internal:5051
ELEC_ALERT_INTERVAL_SECONDS=3600
```

间隔最小60秒。宿主机上的 `localhost:5051` 不等于 AstrBot 容器中的 localhost；Compose 已设置 `host.docker.internal` 映射，后端需监听容器可达地址。也可以把地址改成容器能够访问的 `http://192.168.31.1:5051`，不要在插件中直连 WhuApi。

Compose 已添加独立插件挂载，首次安装需要重建 AstrBot 核心来应用新挂载；不重启 NapCat，不需要新镜像。更新与数据备份方式沿用[部署指南](deploy.md)。
